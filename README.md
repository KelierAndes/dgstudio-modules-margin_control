# 灵猫边控联动（DGStudio 模块）

DGStudio 的灵猫边控模块：**纯数据面模块**（只登记变量、不驱动设备）——
实现自动「**刺激 → 到边 → 冷静 → 恢复**」边控玩法，判定条件与阈值自适应
对标 DG-Lab 官方边控玩法设置页。模块把边控会话整理成变量数值，全部设备
动作只来自「事件流」页画布上的卡片连线，模块不携带任何内置链路、也不直接
下发设备指令。

- DGStudio 核心仓库：
  [DG-Lab-Studio](https://github.com/KelierAndes/DG-Lab-Studio)
- 模块市场仓库：
  [dgstudio-modules-market](https://github.com/KelierAndes/dgstudio-modules-market)

### 数据链路（事件流）

* **模块登记变量**：模块用 `link_params()` 把边控会话整理成的读数登记进
  「事件流」页右侧的变量表——`stim_strength`（刺激器强度）、
  `punish_strength`（惩罚器强度）、`on_edge`（到边标志）、`on_release`
  （释放标志）、`cycles`（循环计数）为只读发布；`pressure`（平滑 + 漏气
  补偿后气压）、`edge`（官方边控会话状态）为可读写；
* **画布接线驱动设备**：用户在画布上把变量表行拖出**读数卡**、经
  **运算卡**（范围映射 / 取大值 / 钳制 / 比较）换算后，末端连「核心变量」
  分类下的**核心写入卡**（`in_strength_a/b` 郊狼、`in_ovc_strength_a/b`
  负鼠、开火 / 脉冲流等）落地到设备——目标设备 / 通道完全由写入卡的参数 id
  决定，模块只读数、不选设备、也不直接下发设备指令；
* **气压回灌闭环**：把「核心读出」的 `BMTR.Pressure` 读数卡接进 `pressure`
  写入卡，模块每拍取原始气压做平滑与漏气补偿后再发布 `pressure`，据此推进
  刺激 / 冷静 / 释放；`BMTR.EdgeState → edge` 同理（app 模式才需要）；
* **闭环由模块维持**：状态机在模块内部按自己的会话状态推进，只刷新上述
  变量；运算不再写在模块配置的临时变量行里，而是一律在画布上连线完成。

模块零内置卡片：画布上不接气压读数就取不到有效气压，不接强度写入卡就推
不出强度——闭环安全待机并在日志提示。建法见「配置与使用」。

## 功能

默认行为（`sensor` 模式）：刺激期从 0 缓升到「刺激强度」，气压高于红线
（或短窗口快速上升）判到边，以「惩罚器强度」短促输出后撤除刺激进入冷静；
冷静满「最小冷静时间」且气压持续低于蓝线才恢复刺激。**边控 5 次（或会话
时长达限）后进入释放期**（助力强度输出），释放满「释放时长」循环计数清零、
重新开始。阈值自适应（每次边控后红线下降、久不到边红线缓降、蓝线按比例
跟随；冷静过久蓝线回升）**默认关闭**，需要时在「阈值自适应」分组打开
对应开关。

### 三种边控模式

| 模式 | 依据 | 行为 |
|---|---|---|
| `sensor`（默认） | 灵猫气压 | 气压闭环（判定条件见下）；边控次数或会话时长达限 → 释放（助力输出），释放期满清零重开 |
| `app` | 官方边控会话 | 跟随 App 边控状态：1 刺激→刺激器输出；2/3 冷静计时/判定→撤除（惩罚窗口同）；4 允许高潮→助力输出；0 停止→待机。次数/时长释放不介入 |
| `off` | — | 不闭环、不动设备，仅提供变量数值供事件流自行取用 |

官方边控状态（核心 `ui/live.EDGE_STATES`）：`0 停止 / 1 刺激 / 2 冷静计时 /
3 冷静判定 / 4 允许高潮`。`app` 模式需要 DG-Lab 4.0 App 的边控玩法会话在跑
（Socket V4 连接）；蓝牙直连的灵猫没有该状态，请用 `sensor` 模式。

### 判定条件（对标官方「判定条件」页）

- **红线**（边缘气压阈值，默认 17.0 kPa）：刺激期气压高于红线判「即将
  高潮」；可要求**连续 N 秒高于红线**（持续判定防抖）。
- **气压跳变**：观测窗口（默认 2 秒）内上升速率达阈值（kPa/s）也判即将
  高潮——对应官方「气压短时间上升差值」，0 = 关闭。
- **蓝线**（恢复气压阈值，默认 15.0 kPa）：冷静期满「最小冷静时间」
  （默认 10 秒）且气压低于蓝线判恢复；可要求**连续 N 秒低于蓝线**
  （默认 5 秒，官方同款）。
- **阈值自适应**（对应官方「阈值自适应调整」）：
  - 刺激阶段：每次成功边控后红线按百分比立即下降；超过等待时长仍未到边，
    红线按速率（%/s）**线性**缓慢下降（按配置基线计算，不复利衰减）；
    蓝线按「跟随百分比」同步下探；
  - 冷静阶段：超过等待时长仍未恢复，蓝线按速率（%/s）上升——恢复变容易；
  - **红线下限**：红线恒不低于「恢复阈值 + 0.5 kPa」——自适应无论累计
    多少，到边判定都不会跌破设定阈值区间（红线不会无声衰减到低气压区）；
  - 红线/蓝线间恒保持 0.5 kPa 安全间隙（蓝线不会越过红线）。
- **漏气补偿**：叠加到气压读数上的固定偏移（腔体漏气读数偏低时调大；
  官方默认 3 kPa）。

### 释放触发（满足其一进释放期）

| 条件 | 配置 | 官方对应 |
|---|---|---|
| 边控次数 | `边控次数释放 (轮)`，默认 5，0=不限 | 「指定边控次数后，允许高潮释放（固定模式）」 |
| 持续时长 | `持续时长释放 (秒)`，默认 0=关闭 | 「游戏进行指定时长后，允许高潮释放」 |
| App 会话 | 状态 4（仅 app 模式） | 「允许高潮」 |

释放期以「助力强度」经刺激器变量持续输出；「释放时长」满后循环计数清零、
重新开始刺激（0 = 保持释放直到暂停/失联）。

### 安全设计

- **全程事件流通道**：状态机零直接设备命令；惩罚、刺激都只是变量数值，
  删掉画布上对应的核心强度写入卡即彻底断开该路输出。
- **失联判停**：有效气压须高于 0.05 kPa 且读数在「气压失联判停」秒数
  内有变化，否则闭环归零待机（每 30s 至多提示一条日志）——静息清零后
  0 附近抖动不再引发待机/刺激抖动。
- **暂停按键**：负鼠物理按键绑定「边控闭环 暂停/恢复」，暂停即把两路强度
  变量归零、画布上的核心写入卡下一拍随之落地为 0，可随时掐断闭环；
  「灵猫气压清零」按键同控制页按钮。
- **停止归零经事件流**：停止/卸载模块时把两路强度变量归零，画布上的核心
  强度写入卡下一拍随之落地为 0；画布里没接强度写入卡就不动设备（不会误清
  手动强度）。
- **红线/蓝线安全间隙**：自适应后蓝线恒不越过红线（至少低 0.5 kPa），
  红线恒不低于「恢复阈值 + 0.5 kPa」；缓降按配置基线线性计算，
  自适应累计只增不回跳（重开模块复位）。
- **读数有效性**：有效气压须高于 0.05 kPa 且在 `sensor_timeout_s` 内
  有变化——设备离线（气压恒 0.0）、「气压清零」后静息、读数冻结均
  判定无效，闭环归零待机，不会在无反馈时盲推强度。
- **零内置链路**：模块不携带任何内置卡片或兜底连线——读数与写入全靠
  「事件流」画布上的连线；画布为空 = 不取气压、不驱动设备（安全待机）。
- **设备路由交还核心**：模块只登记变量、不选设备；核心写入卡的目标 =
  核心输入参数 id（`in_strength_a/b` 郊狼、`in_ovc_strength_a/b` 负鼠），
  设备定位按核心输入路由语义（各类型首台，跳过灵猫）。

## 安装

DGStudio「模块」页 → 在线列表找到「灵猫边控联动」→ 安装并启动
（无第三方依赖）。需要带「事件流」页的核心版本（DGStudio v0.3.0 起；
旧核心的输入 / 输出映射表方式已停用）。

## 配置与使用

1. 连接灵猫（蓝牙直连或 Socket V4）与输出设备；先用灵猫卡片上的
   「**气压清零**」校准静息 0 点，再按佩戴后的静息气压调整
   「边缘气压阈值 / 恢复气压阈值」（默认 17.0 / 15.0 kPa，同官方）。
2. 在「事件流」页右侧变量表里把需要的行拖到画布，连成下面的最小链路
   （执行流走核心常驻的 50 毫秒节拍，无需手动播放）：
   - **读气压**：把「核心读出」分类的 `BMTR.Pressure` 读数卡连到 `pressure`
     变量的**写入卡**（`edge` 变量同理接 `BMTR.EdgeState`，app 模式才需要）；
   - **推强度**：把 `stim_strength` / `punish_strength` **读数卡**经「取大值」
     **运算卡**连到「核心变量」分类的强度**写入卡** `in_strength_a`、
     `in_strength_b`；
   - 两路取最大值即 `max({stim_strength}, {punish_strength})`，用画布上的
     max 运算卡完成，不再写进模块配置。

   多台灵猫时把喂给 `pressure` 写入卡的那张读数改指向目标（如
   `BMTR.2.Pressure` 读数卡）；分设备驱动（郊狼 A ← 惩罚、负鼠 A ← 刺激）
   则把 `punish_strength` 读数卡连 `in_strength_a` 写入卡、`stim_strength`
   读数卡连 `in_ovc_strength_a` 写入卡。
3. 玩法参数在「模块」页按需调整；变量表每行实时显示当前值（模块卡片不再
   有独立的「实时数据」区）。读不到气压时日志会提示「尚未读到有效气压」，
   先检查画布上是否已把 `BMTR.Pressure` 接进 `pressure` 写入卡。

### 变量数值（7 个）

| 变量 | 说明 |
|---|---|
| `{pressure}` | 平滑 + 漏气补偿后气压 (kPa) |
| `{edge}` | 官方边控状态 0-4（无会话为 0） |
| `{stim_strength}` | **刺激器强度**（刺激/助力共用一个数据项）：刺激期按爬升时长趋向刺激强度，冷静期维持冷静强度，释放期输出助力强度，其余 0 |
| `{punish_strength}` | **惩罚器强度**：到边进冷静后的惩罚输出，惩罚时长内非零 |
| `{on_edge}` | 到边标志：气压 ≥ 当前红线（自适应后）时为 1 |
| `{on_release}` | **释放标志**：释放期（允许高潮，助力输出）为 1，其余 0 |
| `{cycles}` | **边控循环**：当前轮「到边→冷静」计数；释放完成后清零重新计 |

最小接线（两路取最大值——刺激期与释放期走刺激器强度、到边惩罚窗口走惩罚器
强度，其余时刻 0）：

```
读数卡  stim_strength   ┐
读数卡  punish_strength ┴→ max 运算卡 → 写入卡 in_strength_a
                                      → 写入卡 in_strength_b
```

其它常见玩法：

| 想要 | 事件流画布接法 |
|---|---|
| 只驱动 A 通道 | 删掉画布上的 `in_strength_b` 强度写入卡 |
| 到边瞬间来一下更强惩罚 | 上面 `max(...)` 接线已是此行为（惩罚强度 > 刺激/助力强度时窗口内取惩罚值） |
| 郊狼 A 惩罚、负鼠 A 刺激 | `punish_strength` 读数卡 → `in_strength_a` 写入卡；`stim_strength` 读数卡 → `in_ovc_strength_a` 写入卡 |
| 释放期定时开火助力 | `on_release` 读数卡 →（门控 / If-Else 分支）→ `in_fire` 写入卡（正值开火保持、归 0 停止并恢复） |
| 气压直接驱动强度 | `pressure` 读数卡 → 乘 3 运算卡 → `in_strength_a` 写入卡 |
| 用到边标志触发急停 | `on_edge` 读数卡 → `in_emergency` 写入卡（慎用） |

画布上的运算卡支持四则运算、`abs/min/max/round` 与比较（比较结果为 1/0，
如 `pressure >= 20`）；核心写入卡只落地数值、不做运算。`pressure` / `edge`
两个变量由模块占用（写入卡灌入原始读数、闭环读取并回灌处理后的值），
不要再给它们接别的写入卡。

参数路由解析（各类型首台，跳过灵猫）。

## 常见问题

- **`app` 模式没有反应？** 需要 DG-Lab 4.0 App 的边控玩法会话在跑
  （Socket V4 连接）；蓝牙直连的灵猫没有官方边控状态，请用 `sensor` 模式。
- **启动后设备一动不动？** 模块零内置链路：先按「配置与使用」在画布上接好
  「读气压」（把 `BMTR.Pressure` 接进 `pressure` 写入卡，否则日志提示
  「尚未读到有效气压」）与「推强度」（`stim_strength` / `punish_strength`
  读数卡经运算卡连到核心强度写入卡，否则强度无处落地）两条链路。
- **多台灵猫怎么换绑？** 把喂给 `pressure` 写入卡的那张气压读数改指向目标
  （如 `BMTR.2.Pressure` 读数卡）。
- **画布上的运算卡能算比较吗？** 可以，比较结果为 1/0（如
  `flag = {on_release} + ({pressure} >= 20) * 2`）；核心写入卡只引用
  变量名、落地数值，不写表达式。
- **从旧版（映射表 / 模块内事件卡时代）升级后链路空了？** 核心装载设置时
  会把遗留的 `events` / `temps` / `mappings` / `outputs` 四项一并清除并记
  一条日志；改为按「配置与使用」在「事件流」画布上重建读取与推送链路。
- **气压读数偏低？** 腔体漏气时读数会偏低，调大「漏气补偿」
  （叠加到气压读数上的固定偏移，官方默认 3 kPa）。
